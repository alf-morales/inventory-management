Factory Inventory Management System

A three layer demo application: a Vue 3 single page app talking over HTTP to a Python FastAPI service that serves in-memory data loaded from JSON files at startup. No database, no authentication, no persistence.

System Architecture

Each layer is independently runnable. The client is served by Vite on port 3000 and reaches the API on port 8001 with absolute URLs, so there is no dev proxy in play.

Data Flow: A Filter Change

The four global filters (period, warehouse, category, order status) live in one shared composable. Changing any of them drives the same round trip on every view.

1

User picks a filter

FilterBar in App.vue writes to the shared refs in useFilters.

2

Views react

Each view watches the refs and calls getCurrentFilters(), which maps period to month.

3

Request is built

api.js drops any value equal to all and appends the rest as query params.

4

FastAPI filters

Handlers pass the in-memory list through apply_filters and filter_by_month.

5

Pydantic validates

Typed routes serialize through their response_model before the JSON leaves the process.

6

Vue derives and renders

Raw rows land in refs; totals, charts and badges are computed properties over them.

Notes and Gaps

Client calls endpoints the server does not expose

api.js defines task CRUD (/api/tasks) and purchase order calls (/api/purchase-orders). Neither route exists in main.py, so App.vue logs the failure and falls back to the mock tasks in useAuth.

Backlog.vue is unreferenced

The view exists but has no route and no import. Backlog data is rendered inside Dashboard.vue instead.

All filtering is Python list comprehension

Every request re-filters and re-aggregates the full in-memory list. Fine at this size, but there is no pagination, indexing or caching.

No auth and permissive CORS

allow_origins=["*"] with credentials enabled, and the signed in user is hard coded in useAuth. Local development only.

Writes do not persist

Data lives in module level Python objects populated at import. Restarting the server restores the original JSON fixtures.

Test coverage is backend only

40 pytest cases against the FastAPI TestClient cover inventory, dashboard and the remaining endpoints. There are no frontend unit tests; browser checks run through Playwright MCP.
